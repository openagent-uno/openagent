# Server 1.1.9 beta79

Pins Core 1.1.0b123.

- Sign an account in to a subscription provider from the app. For a provider
  whose endpoint is a local subscription service, `POST
  /api/providers/{id}/sign-in/start` returns the page to open and `POST
  /api/providers/{id}/sign-in/complete` finishes with the code the page hands
  back. The service owns the flow and the tokens; the server only drives it,
  for the agent's owner.
- `GET /api/accounts` also reads a service's accounts from its
  `/admin/diagnostics` when `/health` does not list them, and marks such
  providers with `sign_in: true`.
- The live view of a session reports the model that answered each run (Core
  beta123).
- App (beta 60): "Sign in again" on an expired account and "Add account"
  under a subscription's accounts.
