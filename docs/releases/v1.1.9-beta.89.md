# Server beta89 — bounded fresh history authorization

The standalone product adopts the public Core beta140 cohort. Unified history
snapshot capture rechecks current grants through Core's batch visibility API,
avoiding a separate query for every principal and candidate row. SQL candidate
filtering, current per-page checks, host authorization and cursor isolation remain
in place. No permission cache or stored-history migration is introduced.

A 50,000-row explicit-grant fixture measured first-page capture at 15,125 ms
before and 593 ms after, with identical IDs, ordering and snapshot digest.
Authorization SQL reads fell from 250,001 to 251. The owner-only fixture remained
approximately 183–185 ms. These are controlled SQLite measurements, excluding
remote transport and rendering; they do not establish a universal loading gain.

All 26 operational API checks passed against the candidate, including a new
501-grant snapshot regression with a bounded query count, revocation before the
next page and rejection of another principal's cursor. Public installed-wheel,
three-platform and live-host qualification are separate release gates.

The public release passed all three host ownership suites, installed-product
qualification and repeated responsive provider/session UI checks. Local installed
qualification passed 625 tests and 90 subtests, plus 20 Custom Views and 26
operational API contracts. The published installer was downloaded again and
matched the sealed bytes. Seven deployed hosts retained their protected keys,
identity, model settings and toggles; real provider requests passed on each.
