# OpenAgent v1.1.0-beta.25: one-shot child authorization repair

Product beta 25 fixes the remaining production failure in approved one-shot
scheduled tasks. The scheduler correctly claimed the due occurrence, disabled
the one-shot definition atomically, and opened its durable run row. The real
child chat then crossed a second Runtime admission boundary with a new session
id, where the authority check could no longer recognize the already-admitted
occurrence and rejected it as revoked.

The authority now walks only persisted, same-delegation `parent_run_id`
records back to the exact automation occurrence. This keeps that occurrence's
child chat and nested sub-agents authorized until the run publishes, without
making another disabled definition or unrelated session executable. The
one-shot grant is still revoked after completion and the schedule remains
disabled, so it cannot fire twice.

The regression test uses the real durable child Runtime path that failed in
production. The complete product suite passes with 82 tests and 21 subtests.
Product beta 25 remains paired with Core beta 13. The signed desktop App stays
at beta 15 because this repair changes only the server authority layer.
