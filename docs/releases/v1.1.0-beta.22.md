# OpenAgent v1.1.0-beta.22: visual MCP result repair

Friday's `computer_control_computer` produced a valid 1280×920 screenshot of
Chrome on display `:101`. The durable invocation contained the page, including
the Chrono24 Cloudflare checkbox, but the model described the screenshot as
uniformly black. The problem was in the model-facing path: Core's in-process
`tool-search` returned the complete MCP envelope as JSON text, including the
base64 image. Claude sub proxy also flattened image parts inside OpenAI `tool`
messages into text. Neither step gave Claude image pixels to inspect.

Core `1.1.0b11` lifts standard MCP image blocks into runtime `ToolResult.images`
for model calls while preserving the full MCP envelope for durable invocations
and programmatic callers. Claude sub proxy `0.1.4` preserves image and document
parts inside Anthropic `tool_result.content`. The standalone server pins Core
and SQLite adapter `1.1.0b11`; its server and CLI wheels are `1.1.0b22`.

The direct conversion test used Friday's stored screenshot: the same 59,739
PNG bytes survived MCP envelope → Core model result → OpenAI tool message →
Claude tool result, with SHA-256
`c9fb82ecfe73cfd2ba6837ee541a44888410924ace456f5a7931b7719861d973`.
Core's public suite passed 140 tests and 23 subtests; the proxy translation
suite passed 19 tests. Publication and a real Telegram retest are separate
gates, recorded below when complete.

The visual fix lets Friday assess the page and use normal browser controls.
It does not guarantee that Chrono24 will accept an automated session or that a
Cloudflare challenge will clear. Challenge completion must be checked on the
same persistent browser profile, and the account's authenticated state must be
verified after the challenge. Exporting session cookies from another machine
is not the recovery procedure.
