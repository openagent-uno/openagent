# OpenAgent v1.1.0-beta.18: Claude proxy image input

Friday's Telegram bridge stored the user's JPEG correctly, but the media
dispatcher rejected it before calling `claude-sub-proxy`. Its three Claude
models were registered under provider `local` with persisted
`input_modalities=["text"]`. The conservative legacy backfill had treated the
custom provider name as an unknown model; the later media-capability guard
then made this stale declaration blocking. The same latent configuration was
found on Mixout.

OpenAgent Core beta 9 infers `text`, `image`, and `file` for recognised Claude
model IDs even behind a custom OpenAI-compatible provider. Explicit model
metadata remains authoritative. This release updates the product's exact Core
dependency and the dependent Python wheels together. It does not alter the
image generation endpoint or desktop App code.

Before changing live metadata, each subscription proxy was tested with a
synthetic red PNG. Friday's Opus, Sonnet and Haiku, and Mixout's Opus each
returned `Red` through their own local proxy endpoint. Friday's SQLite backup
is `/srv/friday/backups/pre-vision-fix-20261003T145229Z`; Mixout's is
`/home/ubuntu/.openagent/backups/pre-vision-fix-20261003T145747Z`. Both passed
`integrity_check`. Only the verified Claude model rows were updated to
`["text","image","file"]`.

The signed-in Telegram client then sent Friday a synthetic red PNG with a
question about its main color. Friday replied `Rosso.` on Telegram through
`local:claude-opus-4-8`; durable run
`fb1a5c96-eb0c-45cb-8ea4-c067041ee9b5` is `success` and includes the
image attachment. The corresponding two failed runs before correction are
`14a5aa60-d1a5-4cb3-a65c-a3559c23a752` and
`92b8f2e1-6650-4e56-be20-b680c9e78049`.
