# Python product 1.1.9 beta50

Core 92: a timed-out compaction summary retries a sibling model; quieter
automation diagnostics.

- Pins Core 1.1.0b92 (core, gateway, sdk, storage-sqlite). When the compaction
  summary fails for a call-specific reason (timeout, transient error), another
  model of the same provider is tried before giving up; quota, rate-limit and
  auth failures still move to another provider only.
  `OPENAGENT_COMPACTION_FALLBACK_MODEL` is honoured whatever its provider, and at
  most two fallbacks run. Before, an install with a single working provider
  skipped compaction after a timeout and the session kept growing.
- `automation.authorization_required` is no longer logged for a disabled
  automation: it never fires and disabling revokes its grant, so the warning read
  as "an automation is blocked". The authorization result is unchanged.
- Host Tools stays 1.0.0b18; capability-host stays 1.0.0b4; product-config stays
  1.1.0b25.
