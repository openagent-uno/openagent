# Server beta98

Confirmed private-channel resets now select a genuinely fresh conversation.
The old conversation remains readable, the model selection is preserved, and
the current selector survives reconnects and server restarts. The standalone
adapter uses Core's shared command semantics and public storage operations.

Bridge identities are recognized from the authenticated reserved handle as well
as historical client IDs. Reset admission and message submission share a bounded
serialization boundary; a message arriving during reset cannot resume the retired
conversation. Queued commands select the current session after earlier commands
complete. The boundary does not remain locked while a model answers.

Private route normalization preserves the configured provider account, actor and
audience checks. Shared conversation reset remains refused. Failed storage commits
are never acknowledged as successful resets. Vault contents, provider credentials,
catalog rows and long-term memory are not rewritten.

Regression coverage exercises Core command execution with actual SQLite storage,
the next transport input, reconnect persistence, repeated resets, model pins,
storage failures, account/actor isolation and concurrent command/input admission.
Provider quota exhaustion and a text-only model's inability to accept images are
separate model-routing concerns; this release does not claim to fix those.
