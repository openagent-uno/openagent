# OpenAgent v1.1.0-beta.20: server-owned browser and desktop tools

**Superseded for installation by [beta 21](v1.1.0-beta.21.md).** The beta 20
CLI wheel retained a strict Host Tools b4 requirement, while its server uses
b5. The full-install check caught this before production cutover. Use beta 21
for a compatible server plus CLI environment.

The standalone server can opt in to its own `agent-in-chrome` and
`computer-control` capabilities through `server_host_tools.tools`. They use
OpenAgent Tools sidecars on the agent host. App/CLI capabilities keep their
authenticated client destination and are never lent to Telegram or automation.
The server seeds only opted-in product rows, retains an existing disabled row,
rejects collisions with custom rows and forwards display/browser configuration
without channel or provider credentials. `ToolRef` binding remains in Core.

An externally supervised browser can expose its exact profile/CDP endpoint to
the browser sidecar using a verified ownership marker. The sidecar then
disconnects without stopping that browser or a human verification handoff.
Friday uses a dedicated Chrome Stable service with a fixed Xvfb display,
Xauthority, a persistent profile and loopback CDP. The service records the
ownership marker on each start. The original Friday browser service remains
separate. `computer-control` addresses the same virtual display.

The focused product suite passed 11 tests. The host-tools server-contract suite
passed 4 tests with 1 historical checkout skip using the versioned Tools source.
The Tools sidecar regression test passed, its JS syntax checks passed, and the
device-tools 1.0.0b4 wheel was installed outside the source checkout and
imported successfully. The older full product test driver remains unsuitable
for direct pytest collection because it imports removed pre-modular modules and
uses its own `@test` decorator.

On Friday, a consistent SQLite backup passed `integrity_check`. After the
staged server code and configuration were loaded, the service started without a
restart loop and both new MCPs connected. In the real Telegram chat, Friday
used `agent_in_chrome_tabs_context_mcp`,
`agent_in_chrome_computer(action=screenshot)` and
`computer_control_computer(action=get_screenshot)` successfully. It observed
Chrono24's “Just a moment...” challenge in tab 1, and made no clicks or page
changes. This verifies tool discovery, exact server routing, browser/desktop
capture and Telegram response. Chrono24 login and collection access remain
unverified while the site requires interactive verification. General computer
control cannot guarantee passage through every website challenge.

The beta 20 release publishes Python wheels for server deployments. Existing
signed App/CLI bundles continue on their already qualified native bundle; a
new signed multi-platform bundle is a separate release gate.
