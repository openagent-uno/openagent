# OpenAgent v1.1.0-beta.29: default Vault path repair

Product beta 29 makes the standalone Gateway expose the same canonical Vault
directory as the Agent runtime when `memory.vault_path` is omitted.

Production agents normally rely on the `<agent-dir>/memories` default rather
than repeating that path in `openagent.yaml`. The runtime already resolved that
default correctly, but the Gateway copied only the optional raw YAML field.
The App therefore received `503 Vault administration is not ready` from every
Vault endpoint even though the Markdown notes and runtime Vault were healthy.

The Gateway now obtains its path through the Agent's canonical resolver. The
minimal local E2E profile still leaves Vault unavailable unless its fixture
explicitly supplies a path, preserving the profile's module boundary. Tests
cover both cases.

The standalone product suite passes 84 tests plus 21 subtests. Product beta 29
remains paired with Core beta 15 and Tools beta 4. The signed desktop App
remains beta 15 because this repair changes only the server runtime.
