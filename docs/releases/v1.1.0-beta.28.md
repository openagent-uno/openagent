# OpenAgent v1.1.0-beta.28: terminal automation-run repair

Product beta 28 pairs the standalone server with Core beta 15 so terminal
Agent and Team stream events remain terminal all the way through unattended
scheduled-task execution.

A live Friday canary exposed the failure path after the scheduler had already
claimed and started its one-shot occurrence: the configured model returned a
rate-limit `TeamRunError`, but the stream adapter treated the absence of text
deltas as an empty successful stream and issued the entire prompt again through
`generate()`. The durable task row therefore stayed `running` during the
duplicate provider call. Core beta 15 now propagates terminal error and
cancellation events through the normal finalizer, preventing that second call
and allowing the run to become `failed` or `cancelled` promptly.

The scheduler path itself was also exercised with an enabled alternate model:
the one-shot occurrence reached `success`, its exact authorization grant was
revoked, and the temporary definition was removed. The workflow and event
canary reached `success` through the real independent `web-search` MCP and
returned usable results.

Core's source suite passes 151 tests plus 23 subtests. The standalone product
suite passes 82 tests plus 21 subtests. Product beta 28 is paired with Core beta
15 and Tools beta 4. The signed desktop App remains beta 15 because this repair
changes only the server runtime.

### Live end-to-end acceptance

The Friday App sidecar reported server `1.1.0b28` and exactly the three expected
independent web-search tools. A temporary workflow executed a real web search
and returned usable results; an event dispatched that workflow successfully.
A one-shot scheduled task using `moonshot:kimi-k3` then reached `success`,
revoked its one-shot authorization, and was deleted. All temporary workflow,
event, and task definitions were removed after the checks.

The terminal-failure canary used the rate-limited provider path. It reached
`failed` within its execution policy, revoked its one-shot grant, and emitted
zero `agent.run_stream.fallback_to_generate` records. This verifies the fixed
failure behavior without claiming that the external provider quota itself is
available. Independent live search calls also returned results on Mixout and
the shared Performa/Ribel/Yoanna host, including successful fallback from slow
browser engines to DuckDuckGo.

All five SQLite databases were readable in WAL mode after the canaries. Friday
returned `quick_check=ok`; its 855,384,064-byte database had a 2,212,472-byte
WAL. The other WAL files were 601,552 bytes (Mixout), 655,112 bytes (Performa),
4,152 bytes (Ribel), and 469,712 bytes (Yoanna). No database-lock or
`SQLITE_BUSY` error was logged on any service after cutover.

The signed App `1.1.0-beta.15` remains installed and running on the acceptance
Mac. That App already contains the conversation reattachment, pending-message,
sub-agent reasoning-state, and live-stream navigation repairs; beta 28 did not
require another desktop rebuild.
