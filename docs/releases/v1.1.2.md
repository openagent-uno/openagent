# OpenAgent 1.1.2

Stopping or cancelling an operational search could close its SQLite connection
while an executor thread was still checking the FTS index. A production shutdown
reproduced a native SIGSEGV in that exact integrity-check path. Core beta37 now
interrupts the SQL, waits for the worker even across repeated cancellation, and
then permits rollback and connection close. Cancelled index opens also close their
otherwise unclaimed connection. Canonical history and index schema are unchanged.

This stable server/CLI release retains the actionable AI account, authentication,
model and quota errors introduced in 1.1.1, using channel bridges beta15. Existing
native App binaries display those server messages without a binary update.

Validation: four deterministic cancellation regressions (including the public
status path), all 506 Core public source tests and 90 subtests. Installed-wheel
and production stop/start acceptance are recorded in the qualification receipts.

Installed qualification: 506 Core tests and 90 subtests; 417 product tests and
104 subtests on macOS; 420 Linux tests and 101 subtests, including the four
SQLite cancellation regressions. The public installer verified all 40 first-party
wheels. Server and CLI assets are stable; native App binaries retain beta22.

Production acceptance: all three agents authenticate through the existing owner
identity, execute a real Claude Opus 5.5 turn with completed tool discovery, and
survive normal stop/restart. Performa stopped in 2.39 seconds while its SQLite
integrity worker was observed in flight. Thirteen enabled automations retain
authorized owner grants. See the [production receipt](../qualification/product-stable-1.1.2-production.json)
for the public installer, backup, channel scope and infrastructure limits.

Production configuration follow-up, 27 October: Performa, Ribel and Yoanna had
Telegram contact admission but no explicit private owner/operator Vault policy.
Their native Vault and scheduled work remained available while conversational
Telegram turns could not discover it. The repair adds the verified existing
private senders to `runtime_tool_audiences.vault_owner_channels.telegram` on
each installation and restarts only after its active work finishes. This is a
configuration repair on the existing 1.1.2 wheels, with no new server release.
See the [Telegram Vault receipt](../qualification/vault-telegram-2026-10-27.json)
for authenticated bridge search, note creation and reread, authorization boundary
checks and the distinction from external Telegram message delivery.
