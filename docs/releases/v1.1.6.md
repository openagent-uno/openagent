# Standalone 1.1.6 — shared commands, local candidate

The standalone gateway delegates session commands to Core beta42. Failed resets
keep their failed outcome across the WebSocket and typed bridge transport; a
provider forget failure does not rotate or announce completion. Channel bridges
beta16 share the catalogue with embedding hosts. See [the protocol](../../packages/channel-bridges/PROTOCOL.md).

The server, CLI, identity, transport, dashboards, support integration and MCP
bridge advance to 1.1.6 as a compatible cohort: identity/transport/dashboard/support
1.1.5 pin Core b41 exactly and cannot resolve with b42. Host Tools B7 and product
config b20 retain their immutable public versions and bytes. Core/SQLite are beta42 and bridges
beta16. The installed candidate manifest and checks remain local until review.
Existing identities, updater endpoints, native bundles and release bytes are
preserved. This page does not claim publication, deployment or live-provider QA.

The normal installed closure passes dependency resolution and pip check
(159 packages) without no-deps or source overlays. Installed command regression
checks pass 21 cases, including actual StreamSession cancellation and truthful
failed reset through Core, gateway and typed transport. The bridge suite passes
340 tests and 86 subtests; Core passes 687 tests and 97 subtests. Publication,
real providers and signed native clients remain separate acceptance gates.

The checksum-pinned installer selects product 1.1.6 and Core beta42 candidate
manifests. Its fixture verifies server/CLI requirements derive from actual wheel
metadata. The public --check path must be run after publishing these exact bytes
before updating the site or announcing public installer acceptance.

The same beta42 family additionally includes MCP startup closed-session recovery.
Product1.1.6 and bridgeb16 wheel bytes remain unchanged: only local acquisition
hashes, manifests and installer pins are refreshed for the new Core family.
All seven project metadata dictionaries and packaged runtime sources remain
identical to their original build, apart from source-only UV acquisition hashes.
