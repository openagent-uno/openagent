# OpenAgent v1.1.0-beta.38: shared connector product release

This Python product candidate packages the shared official connector catalog and
local connection controls for the standalone server, CLI and MCP bridge. It pins
the published connector adapter/runner contract `0.1.2` and targets Core/SQLite
beta 21's terminal, Vault Git initialization and Windows snapshot fixes.
Server-owned identity, local encrypted credentials, authorization and existing
MCP configuration retain their current contracts.

The coordinated Python set contains nine wheels. The seven product components
move to `1.1.0b38`; the independently versioned host tools `1.0.0b5` and product
configuration `1.1.0b17` retain their existing versions. The App renderer/native
release has its own qualification and version; this Python wheel set does not
establish signed desktop acceptance.

Core beta 21 contains only the independently qualified regressions. The advanced
derived-content privacy APIs remain a separate frozen draft and are not installed
by this release. Shopify enrollment remains explicitly unavailable, and the
common authentication deployment retains its provider activation controls. This
does not prevent the catalog from showing the official integrations together with
custom marketplace MCPs or using separately available token/account connectors.

The [connector guide](../site/guide/connectors.md) covers server/App/CLI connection
controls. The [status page](../site/guide/connector-status.md) distinguishes real
provider acceptance from catalog, mocked account and packaging checks. Existing
connections keep the app registration that issued their credentials; migration
to a common app requires a new consent.

The normal server installer now acquires the platform runner through the same
consumer lock, manifest/archive/binary checks used for frozen server builds. It
downloads the separately versioned connector Python wheel, installs a verified
runner beside the environment's Python executable, and rechecks an existing
bundle before reuse. No local Go build or manual runner setup is required.
Explicit `runner_path` configuration and the existing frozen-bundle lookup retain
their precedence.

Release qualification is recorded with the wheel/source manifest and separate
installed-consumer receipt. Publishing waits for source and asset review. A
manifest marked `development-unqualified` is build evidence, not a claim of real
OAuth/provider acceptance or a completed desktop release.
