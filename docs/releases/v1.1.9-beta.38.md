# Python product 1.1.9 beta38

Custom View publishing stays retryable after a failed transaction. A revision
bundle left behind by a publish that never committed no longer blocks every
later update at that revision. Write-lock contention is reported as a
retryable `busy` result (REST `ui_view_busy`, 503) instead of a generic
"temporarily unavailable", and every `ui-manager` failure says whether a retry
can help. `ui_get_schema` now describes each component's properties and data
shape, collection components accept the renderer's `data` alias, and
validation errors name the supported alternatives. Core beta83 is unchanged.
Existing identity, vault, automation and Custom View data remain in place.
