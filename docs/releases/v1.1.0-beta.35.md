# OpenAgent v1.1.0-beta.35: Performa session and scheduler reliability

Product beta 35 pins Core beta 20 after investigating Performa's real
interruptions on 10–12 October 2026. Thirty gateway WebSocket failures recorded
`database is locked` while persisting session metadata. The subsequent server
restarts were requested through the authenticated client (`ws_command`), rather
than unexplained process crashes.

A shared SQLite reader can retain a WAL snapshot that another writer has
advanced. Promoting that reader to a writer fails immediately with
`SQLITE_BUSY_SNAPSHOT`, regardless of the configured busy timeout. Session
metadata now acquires a dedicated `BEGIN IMMEDIATE` transaction before reading
or merging metadata and projects the normalized session on that connection.
Runtime-owned transcript and user identity fields remain untouched. Borrowed
host transactions retain their existing connection contract.

Scheduled-task polling also reads a fresh connection, so a stale shared reader
cannot repeatedly return an occurrence already advanced by the atomic
claimant. WAL checkpoint cursors are consumed and closed explicitly.

Performa additionally recorded a compaction failure caused by a missing
`_is_cloud_model_id` import. Core restores the existing model-family classifier,
allowing background jobs to select their plain summarizer and preserving the
distinction between a self-hosted model and a local proxy to a cloud model.

Regression tests reproduce the stale-reader metadata failure, verify fresh
schedule reads after an atomic claim, and exercise real background summarizer
selection. Core's public suite passes 168 tests and 23 subtests, and the four
incident regressions pass against the exact built wheel. Historical legacy
fixtures have 24 failures, 63 passes and two skips both before and after this
change; they do not constitute new regressions.

The signed desktop remains beta 15: these repairs execute on the Agent server.
