# OpenAgent 1.1.0 beta68

The owner can update the agent's editable persona from a verified private channel turn, using the same canonical identity service as the desktop Settings API. Mapped Slack and Discord turns use the actual current network-user mapping; legacy Telegram and WhatsApp bridges require an explicitly configured owner sender and the exact private bot/account route. No bridge impersonates the installation owner. Shared audiences, delegated/background runs, changed mappings/accounts and revoked ingress cannot rewrite the global persona. The immutable framework prompt stays unchanged.

Owner catalog and automation management now recognize the mapped-channel path too. Private WhatsApp owner policy follows the same explicit, revocable rules as Telegram for vault and management access. Device-owner REST remains supported. Identity writes recheck authorization after acquiring the file lock, preserve unrelated YAML, retain revision conflicts and hot-apply without a restart. Identity change notifications use the product wire contract without importing a removed Core gateway.

Regression coverage exercises persona management and revocation for all four channels, the existing identity/REST fixtures, and attachment delivery in live, final and quiet modes for Telegram, WhatsApp, Slack and Discord. Core/SQLite beta33 and channel bridges beta13 remain pinned. Real provider acceptance is recorded separately from deterministic installed tests.
