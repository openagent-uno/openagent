# Server beta 81 and App beta 61 — providers, accounts and loading

Provider management is organized around independent named connections and
subscription accounts, with text/multimodal, image, TTS and STT models inside.
The server delegates built-in Claude/Codex OAuth and inference to Core beta129;
new connections require no external subscription proxy process.

Core owns credential rotation, account-bound dispatch, typed settings and
budget groups. Settings refreshes preserve drafts, account changes reset owned
media state, and session rendering avoids repeated work on immutable history.
Coordinator RPC connections are reused while every request still performs a
fresh authorization check. Complete context reports run off the event loop
with access checked again before publication.

See [models](../site/guide/models.md), [performance evidence](../performance-2026-11-17.md)
and [provider design QA](../design/providers-2026-11-17/design-qa.md).
Explicit legacy migration requires a cold backup, drained runtime, stopped
credential writers and a tested token-aware rollback. Existing external
compatible providers remain supported until migrated.

Local qualification includes 616 product tests, 90 subtests and one optional
skip, installed Core qualification (1186 tests, 188 subtests, two optional skips),
real Iroh member revocation/outage and real Electron enrollment/tool execution.
Release CI and native artifact receipts qualify the final published cohort.
