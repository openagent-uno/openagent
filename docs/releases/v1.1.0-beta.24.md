# OpenAgent v1.1.0-beta.24: scheduler responsiveness and bootstrap ownership repair

Large, mature agents could stop answering HTTP requests, processing chat turns,
and advancing scheduled work even though their service remained active. The
operational-search bootstrap ran a full SQLite/FTS row-id integrity anti-join
synchronously on the asyncio event-loop thread. On databases with hundreds of
megabytes of search index data, that scan starved every other gateway and
scheduler coroutine. This could look like a locked database or a broken
scheduler while the WAL itself was healthy.

Core beta 13 moves every asynchronous row-id integrity check to a worker thread
and waits for it without concurrently reusing the SQLite connection. The scan
still protects index correctness, but no longer freezes chat, REST, channels,
or automation while it runs. A regression test builds a deliberately blocking
check and proves that an event-loop heartbeat continues until all bootstrap and
checkpoint checks finish off-thread.

Product beta 24 also fixes first-user ownership on newly bootstrapped networks.
Redeeming the exact host-created `auto-bootstrap` invitation now creates the
user and conditionally replaces the local agent's `system` owner placeholder in
one transaction. Ordinary invitations cannot infer or transfer ownership, and
a stale bootstrap invitation cannot replace an existing owner. This makes the
authenticated owner able to review and approve exact scheduled-task, workflow,
and event revisions introduced in beta 23.

The desktop App remains v1.1.0-beta.15 because no native or renderer payload
changed. Server deployments must install Product beta 24 together with Core
beta 13; the release wheelhouse and live rollout are qualified as a single
pair.
