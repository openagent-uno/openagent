# Python product beta18 candidate

This candidate adds version-1 explicit legacy private Telegram bindings to the
standalone gateway. It is required when an operator upgrades an old installation
whose existing `tg:<sender>` histories predate scoped provider-account session
keys. A direct version upgrade without an attested binding can correctly isolate
the new route yet appear to forget the older conversation.

The optional `channels.telegram.legacy_private_sessions` policy binds an exact
provider/binding/bot account and explicit private actors to their existing
selectors. Default scoped identities remain unchanged. There is no primary-key
rewrite, copied transcript, new permission or inferred cross-account adoption.
Private children stay in their actor namespace; groups/topics never fall through
to legacy private history. Source tests cover the normal server factory, default
behavior, four-day/restart continuity, account/binding/actor separation, explicit
reset/child selectors and malformed operator policies.

Core beta53, configuration beta22, full modules beta4, Sessions beta3 and native
App/Host Tools keep their independently verified versions. The seven coupled
Python product wheels become `1.1.9b18`; the unchanged configuration wheel remains
beta22. Exact source/tag/public and installed qualification are separate gates;
this source note does not claim deployment of an existing agent.
