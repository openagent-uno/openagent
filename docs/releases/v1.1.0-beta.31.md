# OpenAgent v1.1.0-beta.31: catalog-aware fallback delivery

Product beta 31 pairs the standalone server with Core beta 17. It includes the
durable scheduled-task retry behavior from beta 30 and makes configured model
fallbacks work with providers stored in the live model catalog.

Fallback references such as `moonshot:kimi-k3` now inherit the catalog
provider's API key, base URL, enabled state, and the model's sampling metadata.
That support also covers user-defined OpenAI-compatible providers instead of
silently skipping every name outside the legacy built-in provider map. A
catalog reload or credential rotation rebuilds the chain with fresh values.

Recurring scheduled tasks still advance each cron occurrence atomically. A
transient provider failure with zero recorded tool invocations enters the
durable request queue with bounded delays of 15 minutes, one hour, and four
hours by default. Retries remain disabled for one-shot tasks, permanent
failures, exhausted chains, and any run that may already have produced an
email, social post, or other tool side effect.

Core's public suite passes 157 tests plus 23 subtests. Dedicated regressions
cover catalog credentials, custom provider base URLs, credential rotation,
delayed retry eligibility, retry deduplication, bounded chains, and the
zero-tool safety gate. Product beta 31 is paired with Core beta 17 and Tools
beta 4. The signed desktop App remains beta 15 because this repair changes only
the server runtime.
