# Beta 52: canonical attachment history and delivery

Status: [official Python prerelease published](https://github.com/openagent-uno/openagent/releases/tag/v1.1.0-beta.52), with all 14 initial assets downloaded over HTTPS and checked in full. A separate post-publication qualification asset records the fresh public-wheel installation.

Standalone consumes the independent [Core beta24 release](https://github.com/openagent-uno/openagent-core/releases/tag/v1.1.0-beta.24), source `28b7d3b304f600adb1c33c7b03d948ce8dc49da2`, manifest SHA-256 `6401435f9475c5fadeee00df550c18e13289489fa0628050e8c3a996c9fd7b0a`. Session history delegates to public `SessionInspection.transcript`; the server no longer copies Core's legacy projection. Original user text and authorized attachment references remain separate from model-only document extraction metadata. Existing view grants remain sufficient to read a transcript, and current authorization is checked before returning it.

The standard attachment sender uses an explicitly selected host publisher. Standalone selects its existing server-host filesystem capability when enabled; ICS selects its existing sandbox publisher. Both persist session-linked CAS references through public Core APIs. Disabling filesystem does not create a replacement reader or select a connected device. View-only grants and revoked or different-session execution cannot publish output.

The Python dependency closure requires seven new beta52 wheels: server, CLI, identity, dashboards, client transport, support integration and MCP bridge. HostTools beta6 and product-config beta18 retain their exact public bytes and original provenance. Support integration's exact Core dependency and the bridge's exact identity dependency prevent borrowing their older wheels. Development UV composition uses same-product local sources; normal release installation uses independently published wheels with exact versions and public checksums.

App beta22's renderer remains unchanged: it already renders images inline, video/audio controls on web and Electron, and downloadable file cards for user and assistant messages. The exact `Attachments.tsx`, `MessageList.tsx`, common attachment normalization and CAS resolver match the beta22 tag. A focused renderer test exercises the actual attachment component before opening its modal. Native mobile retains its documented image/file-card fallback for video and audio.

Source checks passed three immutable-component provenance guards. After publication, a fresh normal environment installed the nine actual public product wheels and official Core beta24: dependency consistency, installed import prefixes, 8 standalone transcript/ACL/publisher cases, one ICS source publisher integration and 12 unchanged App contract/renderer checks all passed (21 checks, zero skips). The media cases exercise actual CAS publication/download and session authority; they do not assert visual playback or real-provider acceptance.

This release route publishes Python wheels. It does not rebuild frozen standalone server binaries or the Electron App. A running wheel server must be restarted after installation. Existing frozen-server users do not receive this repair through these wheels. The existing `/api/update` path does not consume the GitHub wheel manifest, so automatic update is not claimed. Beta51 downloads remain immutable.
