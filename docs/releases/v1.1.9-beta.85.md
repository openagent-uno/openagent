# Server beta85 — deferred linked-tool bodies and explicit account routing

This release consumes the exact public Core beta135 cohort. Session message
reads support the opt-in `tool_details=deferred` projection for App beta64.
Linked tool bodies load when opened through the existing authorized invocation
endpoint. Attachments, message identity, cursors and human/assistant content are
preserved; stored history and default reads remain unchanged.

Core beta135 also provides explicitly declared same-vendor/same-text-model
account fallback before any upstream frame, with per-account sampling, budget
admission and actual-account usage attribution. Existing connections without a
declared group keep exact-account routing. Stateless connection tests remain
bound to the selected account. The App exposes the declared policy per account.

Deterministic operational API qualification now runs with installed release
wheels alongside the existing product and Custom Views suites. It covers detail
and compact-message authorization, preserved storage, attachments and reduction
of a large linked-tool fixture. Release publication and real remote performance
acceptance remain separate from local source qualification. No universal 3x
loading improvement is asserted.

The immutable public release passed all product/host-instance/session-UI jobs.
Local installed-wheel qualification passed 620 product tests, 90 subtests and
the deterministic Custom Views and 25 operational API checks. One earlier source
run encountered retryable Custom View write contention; the isolated Iroh repeat
and the complete installed-wheel run passed. The public installer is sealed to
this product manifest and the exact Core beta135 manifest.
