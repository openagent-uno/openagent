# OpenAgent v1.1.0-beta.36: explicit automation deadlines

Product beta 36 retains Core beta 20's Installation C SQLite, scheduler freshness
and summarizer corrections, and fixes the remaining long-run interruption
exposed during production acceptance of beta 35.

The PWA watchdog had no execution-policy timeout and no operator deadline,
but Product supplied an implicit 960-second Runtime deadline. The real
scheduled occurrence was still working after 25 successful tool calls when
that wrapper cancelled it. The canonical run recorded `timed_out`, while the
task projection incorrectly displayed `Stopped by user`.

Tasks, events and workflows now receive no outer deadline unless an operator
or definition explicitly configures one. Definition-level task/event budgets
continue to be enforced by their executor; the outer Runtime adds its existing
30-second finalization grace. Explicit operator deadlines remain supported.
Task and workflow projections reconcile a canonical Runtime deadline as
`timed_out`, without relabelling genuine user cancellations.

Regression tests run the real durable Runtime and authorization path for an
unbounded task, an explicit short timeout, a genuine user cancellation and a
workflow deadline. Existing long-policy and event-policy tests remain in place.
No database schema, task definition, automation grant, user identity or
desktop bundle changes are required.

The source Product regression gate passes 90 tests and 21 subtests; CLI passes
99 tests with one skip. Core beta 20's public gate remains 168 tests and 23
subtests, with the four original Installation C incident reproductions passing
against its exact wheel.

Installation C's Higgsfield MCP credential remains an independent external issue:
its initialization endpoint returns HTTP 401 and no refresh credential is
configured. This release cannot replace an unavailable external credential.
