# OpenAgent v1.1.0-beta.9 Python artifact receipt

This beta coordinates the installable Python distributions. It consumes
`openagent-core` `1.1.0b5`, `openagent-storage-sqlite` `1.1.0b5`,
`openagent-modules` `1.1.0b2`, `openagent-host-tools` `1.0.0b4` and the
independent tool wheels from `openagent-tools` `v1.0.0-beta.3`. The server and
CLI both install from the same locked wheel set. The core's optional Sessions
module adds exact-run inspection, child navigation, bounded waiting and
cancellation; the local tool bundle adds contextual patching, process and
window discovery, window capture and exact-display targeting.

The candidate was tested on macOS arm64, Python 3.12, from wheels installed
in a temporary environment outside the repositories. Dependency resolution
and `uv pip check` passed. `openagent selfcheck`, server and CLI help, and the
CLI's version command passed. Core public tests passed (121 tests, 23
subtests), independent tools passed (23 tests, one Windows-only skip), CLI
packaging passed (18 tests), runtime/product integration passed (36 tests,
19 subtests), and installed Iroh two-account/two-device scenarios passed
(4 tests, 2 subtests). The native Rust suite and live local MCP computer
sidecar were exercised for the tool source candidate; see the independent
tool repository verification notes. Iroh emitted known FFI event-loop
cleanup warnings after the passing integration scenarios.

The GitHub release manifest intentionally retains
`qualification: development-unqualified`. It is evidence for the Python
artifacts only. Desktop App/CLI native archives, notarization, Windows/Linux
installers, updater transition and a provider-backed interactive session are
separate gates. App/CLI desktop consumer locks still point to the previously
signed `0.1.2` host-tools bundle, so an installed App does not yet expose these
new client-local tools. No production cutover or update-feed switch is implied.

The source package release must be followed by signed, platform-specific
host-tools bundles and App/CLI installers. Update the immutable consumer locks
only after the new archives, signatures and digests are verified on each
platform, then run the packaged application and updater-chain E2E tests.
