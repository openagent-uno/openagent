# Python product 1.1.9 beta48

Core 1.1.0b90. Changing one MCP source no longer disturbs the others, and the
answer an agent or client gets is the real outcome.

- Adding, editing, enabling, disabling or removing a source restarts only that
  source; the rest keep their connections, so a running turn keeps their tools
  (before, adding one source revoked every other source's references, including
  the agent computer's shell, for the rest of the turn).
- Registry writes commit in a dedicated transaction, and create/update answer
  with the committed row. A write used to be reported as failed ("cannot commit
  transaction - SQL statements in progress") although it had been saved.
- If applying a committed change to the live pool fails, the change is still
  reported as saved, with `reload_error`, instead of as a failure.
- `mcp-manager` mutation answers carry `"availability": "next_turn"`: a turn
  keeps the capability snapshot it started with.

See Core `docs/mcp-catalog-changes.md`.
