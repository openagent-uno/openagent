# Beta 53: shared channel sessions and normal runtime delivery

Status: [official Python prerelease published](https://github.com/openagent-uno/openagent/releases/tag/v1.1.0-beta.53). All 15 initial assets and the separate post-publication proof were downloaded anonymously over HTTPS and checked in full. The immutable artifact source is `944b2143ea8e6f70423ff353bcbfce1d57233f58`; the product manifest SHA-256 is `6a2a9f461eac51079e01933c9b37adb33ce8b298a2eca70cf430c7b4ad035c19`.

Slack and Discord can map provider identities explicitly to current network members and enter the installation's existing Runtime, model, catalog, vault and journal. Shared channel/thread session keys include the verified audience and current principal mappings, and exclude the current actor. Each run still uses that actor's own authority. Reordering an audience preserves its session; adding/removing a recipient or changing a mapping opens a new epoch. Unknown members, revoked access and an audience that changes before delivery deny publication. Existing private bridge journals remain intact. Missing identity mapping retains the legacy private transport without enabling shared channels.

Mention context remains bounded to the configured latest 0–100 messages and 64 KiB. Provider history is quoted untrusted context; it does not choose a principal or grant tools. Replies keep the incoming channel/thread topology. Generic files and images use public session-scoped CAS upload/read authorization. Slack WebM/M4A and Discord Ogg/Opus voice attachments use the normal speech-service factory and configuration, including the existing local fallback default and explicit `voice.local_fallback: false` setting. No configured speech route produces the normal voice-unavailable response.

This product release builds only `openagent-framework` beta53. The other eight product wheels retain their exact beta52-family bytes and provenance: CLI, client transport, identity, dashboards, MCP and support integration beta52; HostTools beta6; product-config beta18. The source/entry-set reuse proof covers 169 unchanged files. Standalone keeps public Core and SQLite beta24 and adopts the separately released channel-bridges beta4. Bridge beta4 is independently qualified on Core beta26 and has normal install/import/console smoke on beta24; standalone does not silently switch Core versions.

A fresh environment installed the actual public product wheels and complete SDK extras with public Core24 and bridge4. All 159 exact resolved distribution versions, installed import prefixes and dependency consistency checks passed. The installed test batch passed 91 tests and 84 subcases with zero skips. It exercises the real public Runtime, SQLite, CAS, normal delegation and speech-worker protocol with deterministic provider/media fixtures. These checks do not establish real speech decoding or a live Slack/Discord bot grant. See the [product qualification receipt](../qualification/product-1.1.0b53-2026-10-22.json) and [independent bridge receipt](../qualification/channel-bridges-0.1.0b4-2026-10-22.json). Slack live acceptance remains separate. Real Discord end-to-end acceptance was explicitly excluded and is not claimed.

The [checksum-pinned installer](https://github.com/openagent-uno/openagent/releases/download/v1.1.0-beta.53/install.sh) selects this mixed product family and the exact independently released bridge wheel. A wheel server needs a normal restart after installation. No frozen server or Electron App was rebuilt, no automatic updater was qualified, and no website deployment was performed by this route. Earlier releases remain immutable. The [post-publication proof](https://github.com/openagent-uno/openagent/releases/download/v1.1.0-beta.53/post-publish-qualification.json) records the fresh installed checks separately from the initial manifest.
