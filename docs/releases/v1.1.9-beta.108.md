# Server and CLI 1.1.9b108

The scheduled task and workflow HTTP endpoints use the durable manual
automation entry point in Core 1.1.0b170. The Server keeps the existing
run identifiers, task grant identity, workflow `api` trigger and stop
routes. The Runtime still checks the active grant at execution time.

An authorized request reserves a run before dispatch. An identical retry
uses the same projection. The HTTP endpoint returns `202` while the run
is still pending, `200` for a completed occurrence and `409` if the key
is reused with different inputs or an incompatible occurrence. A stop
can also cancel a run that has been reserved and is still queued.

The regression suite exercises both HTTP routes against a real SQLite
database, with replay during and after execution, changed input, and
an unapproved task. The product qualification runs it on the installed
wheel cohort.
