# Server beta 115

Clients can request interleaved text and tool cards from the session messages
endpoint. The server returns display segments when Core can match the stored
stream to the published answer and all of its visible tool calls. Other
histories remain readable as ordinary message pages.

An authorized interactive call marked read-only or idempotent can wait for
the same device to reconnect within its original deadline. A retry reuses
the call ID and checks the grant, device and tool contract again. A call
classified as mutating fails before dispatch if the device is offline.
If that call's delivery becomes uncertain after dispatch, the gateway reports an
indeterminate result without retrying.

Slow Iroh responses keep sending as long as the peer makes progress. A
stalled write expires and reports a transport failure. Slow readers apply
backpressure to the sender. The download endpoint verifies files in bounded
chunks and checks the current permission before sending the first byte. Its
release tests cover both public download routes, checksums and client disconnects.

With live delivery enabled, Telegram updates a separate message for each
delegated agent while the parent turn is running. Each child message carries
its own narration, current tool and final outcome. An explicit rate limit
pauses edits and typing in that chat. Updates accumulated during the wait
are combined before delivery resumes. The bridge allows up to 90 seconds
for a delivery and reports when the requested wait exceeds that deadline.
