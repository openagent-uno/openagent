# Python product 1.1.9-beta.11

This cohort repairs Custom View revision publication and adopts the Core
async-summary deadline and provider-error classification contract.

- An additive database guard rejects head changes to absent revision rows.
  Updates persist the immutable definition, sources and actions before the
  head CAS, in the existing SQL transaction.
- Missing or damaged revisions have a stable recovery error across REST,
  WebSocket and the principal-bound toolkit. Reads verify the selected revision
  and retain ACL checks; they never substitute a different definition.
- Historical repairs are an operator action with a private backup and verified
  bundle evidence; migration does not rewrite a user's view or live data.
- Qualification runs on hosted machines against installed public packages,
  including root tests and the deterministic Custom Views protocol suite.
  The two protocol fixtures explicitly declare their authenticated identity.

Native App 1.1.0-beta.26, Host Tools B15, Device Tools beta18 and the native
computer helper remain independently versioned. The server fixes require no
new native client build. Publication and host acceptance are recorded separately
in the qualification receipt.
