# OpenAgent v1.1.0-beta.30: resilient scheduled-task delivery

Product beta 30 pairs the standalone server with Core beta 16 so a transient
model-provider outage no longer discards a recurring scheduled-task
occurrence until its next cron slot.

The scheduler still claims and advances a due occurrence atomically, avoiding
duplicate cron dispatch. If the resulting run fails because of rate limiting,
overload, unavailable provider capacity, or a timeout, it now enters the
durable task-request queue with bounded delays of 15 minutes, one hour, and
four hours by default. Operators can tune or disable that sequence with
`OPENAGENT_SCHEDULED_TASK_RETRY_DELAYS_SECONDS`.

The safety boundary is explicit: automatic retry is allowed only when the
failed run has recorded zero tool invocations. Once a run has called any tool,
OpenAgent cannot prove that an email, social post, or remote mutation did not
land, so it does not retry automatically. One-shot tasks, disabled tasks,
permanent failures, and exhausted retry chains are also left terminal. The
original provider error remains in task history together with the queued retry
receipt instead of being replaced by a generic automation-wrapper message.

Core's public suite passes 155 tests plus 23 subtests. Dedicated regressions
cover delayed claim eligibility, retry deduplication, bounded chains, the
zero-tool safety gate, permanent failures, and preservation of the root
provider error. Product beta 30 is paired with Core beta 16 and Tools beta 4.
The signed desktop App remains beta 15 because this repair changes only the
server runtime.
