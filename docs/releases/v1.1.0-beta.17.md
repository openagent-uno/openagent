# OpenAgent server v1.1.0-beta.17: private Telegram vault access

The standalone server can explicitly grant its owner access to the agent vault
through a verified Telegram bridge. The bridge has a separate technical
principal, so owner-only vault policy previously hid `vault` and `vault-gate`
from private Telegram turns even while both MCP processes were healthy.

Configure the exact owner sender ID in both places:

```yaml
channels:
  telegram:
    allowed_users: ["<owner Telegram numeric ID>"]
runtime_tool_audiences:
  vault_owner_channels:
    telegram: ["<owner Telegram numeric ID>"]
```

The grant applies only when a live, private `tg:<ID>` turn is authenticated as
the Telegram bridge and both allowlists contain the same ID. It also covers
`vault-gate` and vault note reads in native memory authorization. It does not
apply to WhatsApp, other Telegram senders, shared conversations, or deferred
work. The existing `runtime_tool_audiences.vault: installation` policy retains
its separate, broader meaning.

This is a server-wheel update over the beta 16 product dependency set. Core,
Tools, CLI and App code are unchanged.
