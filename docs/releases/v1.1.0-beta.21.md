# OpenAgent v1.1.0-beta.21: compatible server and CLI packages

Beta 20 introduced opt-in server-owned browser and desktop capabilities. The
first full-install smoke test found that its unchanged CLI wheel still pinned
`openagent-host-tools==1.0.0b4`, while the server now requires `b5`. Beta 21
updates the CLI dependency and advances the server and CLI package versions so
they can be installed together with `openagent-device-tools==1.0.0b4`.

The server-owned capability design and Friday's staged Telegram browser and
desktop test are documented in [beta 20](v1.1.0-beta.20.md). The installation
must pass `uv pip check` before a production switch. The release includes Python
wheels; signed desktop bundles are a separate qualification and release.

## Publication and production verification

Commit `37a7531e34b3d3aeb9bd149133cce16bd31f3778` was pushed to
`openagent/main` and tagged `v1.1.0-beta.21`. The GitHub prerelease includes
nine Python wheels and `release-manifest.json` (SHA-256
`e56049838fba5643e0a74e9776ce93aff516d67e362d2498d6395df63dd555f2`).
All ten downloaded release assets matched the local clean-source build.
OpenAgent Tools beta 4 supplies Device Tools b4.

Friday on Bluehost and Mixout on OVH now run Server b21, CLI b21, Host Tools
b5, Device Tools b4 and Core b10. Each new environment passed `uv pip check`
and `openagent selfcheck`; both live health endpoints returned `1.1.0b21` and
their systemd services reported zero restarts. Immediately before switching,
SQLite backups passed `integrity_check`: Friday at
`/srv/friday/agent/backups/openagent-pre-beta21-20261004.db` and Mixout at
`/home/ubuntu/.openagent/backups/openagent-pre-beta21-20261004.db`. The beta 19
release directories remain available for rollback.

In the real Friday Telegram chat after the beta 21 cutover, Friday invoked
`agent_in_chrome_tabs_context_mcp`, `agent_in_chrome_computer` with screenshot,
and `computer_control_computer` with get_screenshot. It reported one Chrono24
tab and successful 1280x800 browser and 1280x920 desktop captures. Chrono24
still displayed its Cloudflare challenge; no CAPTCHA was clicked or login
verified. Mixout's server-owned browser/computer tools remain disabled until a
dedicated display and browser are configured on that host.

A second real Telegram run tested an interactive browser path: Friday created
tab 2, navigated to `https://example.com/`, read the page to find its current
“Learn more” link, clicked the link with `agent_in_chrome_computer`, and read
the resulting URL and title as
`https://www.iana.org/help/example-domains` / “Example Domains”. The initial
JavaScript tool call used an invalid schema, then Friday corrected it and
completed the check. Chrono24 remained in tab 1 without a click. This proves
ordinary browser interaction on the deployed package, not access through the
Chrono24 site challenge.
